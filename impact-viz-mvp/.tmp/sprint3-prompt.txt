## DAY 11: Loader with Dependency Ordering + Batch Transactions

### Goal
Load validated staging data into production tables in correct FK dependency order, using batch transactions.

### 1. Create lib/import/loader.ts

```typescript
import { SupabaseClient } from '@supabase/supabase-js';
import { ImportProgressEmitter } from './progress-emitter';

export type LoadPhase = 'investees' | 'holdings' | 'users' | 'contributions' | 'metrics';

// Dependency order — MUST load in this sequence to satisfy FKs
export const LOAD_ORDER: LoadPhase[] = ['investees', 'holdings', 'users', 'contributions', 'metrics'];

export interface LoadResult {
  phase: LoadPhase;
  inserted: number;
  updated: number;
  skipped: number;
  failed: number;
  errors: Array<{ rowId: string; message: string }>;
}

export interface LoadOptions {
  batchSize?: number; // default 500
  upsertMode?: 'insert_only' | 'upsert'; // default 'upsert'
  dryRun?: boolean; // if true, validate but don't write
}

export async function loadStagingToProduction(
  supabase: SupabaseClient,
  importJobId: string,
  options?: LoadOptions
): Promise<LoadResult[]>
```

Implementation details:

**For each phase in LOAD_ORDER:**

1. Fetch staging rows in batches of `batchSize` (default 500) where:
   - `import_job_id = importJobId`
   - `validation_status IN ('valid', 'warning')` (skip 'invalid')
   - `action_taken = 'pending'`

2. For each batch, process in a single transaction:
   - Resolve cross-references (e.g., investee_id from staging_import_investees.final_id)
   - Attempt upsert based on match_criteria from mapping profile
   - On success: update staging row `action_taken = 'create'` or `'update'`, set `final_id`
   - On failure: update staging row `action_taken = 'error'`, increment records_failed

3. **Phase: investees**
   - Target table: `investees`
   - Match on: `display_name + country` (if no EIN) or `ein` (if present)
   - Also check `_enrichment.charity_id` — if set, link `charity_id` on investee
   - After insert/update: set `staging_import_investees.final_id`

4. **Phase: holdings**
   - Target table: `holdings`
   - Resolve `investee_id` from `staging_import_investees.final_id` via display_name match
   - Match on: `portfolio_id + name`
   - After insert/update: set `staging_import_holdings.final_id`

5. **Phase: users**
   - Target table: `profiles` (and optionally `portfolio_members`)
   - If user email matches existing `auth.users`: link, set role in `portfolio_members`
   - If no match: create profile stub with `display_name`, flag for invite
   - After: set `staging_import_users.final_profile_id`

6. **Phase: contributions**
   - Target tables: `tax_contributions` AND `holding_contributions`
   - Resolve `holding_id` from `staging_import_holdings.final_id`
   - Insert into `tax_contributions` with all enriched fields
   - If `holding_id` present, also insert into `holding_contributions`
   - Match on: `portfolio_id + contribution_date + amount_usd + recipient_name` (avoid duplicates)
   - After: set `final_tax_contribution_id` and `final_holding_contribution_id`

7. **Phase: metrics**
   - Target table: `metric_facts`
   - Resolve `holding_id` from `staging_import_holdings.final_id`
   - Ensure `metric_code` exists in `metrics` table; skip if not
   - Match on: `holding_id + metric_code + period_start`
   - After: set `staging_import_metrics.final_id`

8. Update `import_jobs` counters after each batch:
   - `records_loaded += inserted + updated`
   - `records_failed += failed`

9. Emit progress events via `ImportProgressEmitter` after each batch.

## DAY 12: Audit Logging

### Goal
Write before/after snapshots to import_audit_log for every DB change, enabling precise rollback.

### 1. Create lib/import/auditor.ts

```typescript
import { SupabaseClient } from '@supabase/supabase-js';

export interface AuditEntry {
  importJobId: string;
  tableName: string;
  operation: 'insert' | 'update' | 'skip' | 'error' | 'rollback';
  recordId: string;
  stagingTable?: string;
  stagingRowId?: string;
  dataBefore?: Record<string, unknown>; // for updates
  dataAfter?: Record<string, unknown>;
  errorMessage?: string;
}

export class ImportAuditor {
  private supabase: SupabaseClient;
  private importJobId: string;
  private buffer: AuditEntry[] = [];
  private flushInterval: ReturnType<typeof setInterval>;

  constructor(supabase: SupabaseClient, importJobId: string) {
    this.supabase = supabase;
    this.importJobId = importJobId;
    // Auto-flush every 5 seconds to avoid losing audit trail on crash
    this.flushInterval = setInterval(() => this.flush(), 5000);
  }

  log(entry: Omit<AuditEntry, 'importJobId'>): void {
    this.buffer.push({ ...entry, importJobId: this.importJobId });
    // Flush immediately if buffer is large
    if (this.buffer.length >= 100) this.flush();
  }

  async flush(): Promise<void> {
    if (this.buffer.length === 0) return;
    const toFlush = [...this.buffer];
    this.buffer = [];
    await this.supabase.from('import_audit_log').insert(
      toFlush.map(e => ({
        import_job_id: e.importJobId,
        table_name: e.tableName,
        operation: e.operation,
        record_id: e.recordId,
        staging_table: e.stagingTable,
        staging_row_id: e.stagingRowId,
        data_snapshot: e.dataBefore || e.dataAfter
          ? { before: e.dataBefore, after: e.dataAfter }
          : null,
        error_message: e.errorMessage,
      }))
    );
  }

  async close(): Promise<void> {
    clearInterval(this.flushInterval);
    await this.flush();
  }
}
```

## DAY 13: Reconciliation Engine

### Goal
Compare source staging data vs loaded production data to detect discrepancies.

### 1. Create lib/import/reconciler.ts

```typescript
import { SupabaseClient } from '@supabase/supabase-js';

export interface EntityReconciliation {
  entity: string;
  sourceCount: number;
  loadedCount: number;
  skippedCount: number;
  failedCount: number;
  matchRate: number; // loadedCount / sourceCount
  // Financial totals (for contributions)
  sourceTotalAmount?: number;
  loadedTotalAmount?: number;
  amountDelta?: number;
  amountDeltaPercent?: number;
  // Issues
  missingIds: string[]; // staging IDs that have no final_id (sample, max 10)
  duplicateWarnings: string[]; // any detected duplicates
  withinTolerance: boolean; // matchRate >= threshold (default 0.99)
}

export interface ReconciliationReport {
  importJobId: string;
  generatedAt: string;
  overallSuccess: boolean;
  entities: EntityReconciliation[];
  summary: string; // plain English summary
  actionItems: string[]; // list of things to fix
}

export async function generateReconciliationReport(
  supabase: SupabaseClient,
  importJobId: string,
  tolerancePercent?: number // default 1% delta allowed
): Promise<ReconciliationReport>
```

Implementation for each entity:

**investees:**
- Source count: `COUNT(*) FROM staging_import_investees WHERE import_job_id = ? AND validation_status IN ('valid','warning')`
- Loaded count: `COUNT(*) FROM staging_import_investees WHERE import_job_id = ? AND action_taken IN ('create','update')`
- Missing: rows where final_id IS NULL and action_taken != 'skip'

**holdings:**
- Same pattern as investees

**contributions:**
- Source count + SUM(transformed_data->>'amount_usd') from staging
- Loaded count + SUM(amount_usd) from tax_contributions WHERE id IN (SELECT final_tax_contribution_id FROM staging_import_contributions WHERE import_job_id = ?)
- Amount delta = |source_total - loaded_total|
- Delta percent = delta / source_total * 100

**metrics:**
- Source count vs loaded count

Store the report JSON in `import_jobs.reconciliation_data`.

## DAY 15: Rollback + Partial Rollback

### Goal
Enable full or partial rollback of an import using the audit log.

### 1. Create lib/import/rollback.ts

```typescript
import { SupabaseClient } from '@supabase/supabase-js';

export type RollbackScope = 'full' | LoadPhase; // 'full' or specific entity

export interface RollbackResult {
  scope: RollbackScope;
  recordsReverted: number;
  recordsSkipped: number;
  errors: Array<{ recordId: string; table: string; message: string }>;
  durationMs: number;
}

export async function rollbackImport(
  supabase: SupabaseClient,
  importJobId: string,
  scope: RollbackScope = 'full'
): Promise<RollbackResult>
```

Implementation:
1. Fetch audit log entries for this job, filtered by scope (all tables or specific table)
   - Order by `created_at DESC` (reverse order — undo last operations first)
   - Only process entries where `operation IN ('insert', 'update')` (skip errors/skips)

2. For each audit entry in reverse order:
   - If `operation = 'insert'`: DELETE FROM table_name WHERE id = record_id
   - If `operation = 'update'`: UPDATE table_name SET ... = data_snapshot->>'before' WHERE id = record_id
   - Log each rollback action as new audit entry with `operation = 'rollback'`
   - On error: log but continue (don't stop full rollback on one failure)

3. After rollback:
   - Reset staging rows: UPDATE staging_import_* SET action_taken = 'pending', final_id = NULL WHERE import_job_id = ?
   - Update import_jobs.status = 'rolled_back'
   - Update import_jobs.records_loaded = 0, records_failed = 0

4. For partial rollback (specific entity only):
   - Only fetch audit entries for that entity's table(s)
   - Reset only that entity's staging rows
   - Leave other entities intact
   - Set job status back to 'paused'
